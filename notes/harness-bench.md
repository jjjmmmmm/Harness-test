- 主结果：最高 **76.2（NanoBot）** vs 最低 **52.4（OpenClaw）** = 差 **23.8 分**，同任务集、同模型池，只不同 harness 配置；且 NanoBot 用比四个对手更少的 token 拿最高分（轨迹更长 ≠ 表现更好）
- 模型后端里和腾讯项目直接相关的是：**deepseek/deepseek-v4-flash**——项目固定的 DeepSeek 在矩阵里有独立证据可引用
- 两个突出模式：① 失败大量发生在"语义上看似合理"与"机器可校验输出"的**边界**；② 失败大量发生在**部分进展之后**（看过输入、收到过反馈，但没转化为恢复/落盘/状态）
- 框架两词：**执行漂移**（推理与"判定成败所依赖的东西"脱钩的症状）/ **执行对齐**（harness 保持"推理/状态/动作/评测条件"对应一致的程度）；harness 隐式定义任务的运行时表征——什么算待办、什么算已观察证据、什么算可恢复失败、什么算完成

## 两个洞 → 腾讯项目补的两步

- 洞① 评测的是**完整 harness 配置**，自认"不是对单个 harness 机制的因果分解"；洞② 全部是**描述性测量，无统计检验**（无 bootstrap/CI）
- 补的两步：**单零件消融**（一次只动一处 = 它没做的因果分解，DSH 的 seam/patch 机制使工程可行）+ **置信区间与复测闭环**（把描述性观察升级为检验）

## 合卷两问（闭卷作答 2026-09-23，原样收录；判分按精读文件"合卷"节细则）

**Q1：它怎么把 harness 从"背景"变成"被测变量"？——判 5/5**

① 固定清单：把一切非 harness 因素钉死。每次评测 = 任务 + 模型后端 + harness 配置 + 沙箱环境 + 评测器（R = Run(M, H, E, T)），除 M、H 外全部锁死。分数若有差异，只可能来自模型或 harness。
② 变动：全因子矩阵系统化扫描。6×8×106=5,088（+Codex 106=5,194），每种组合都跑，因此可做边际分析：同一模型在 6 个 harness 下的分布 → 跨 harness 方差（harness dependence，Figure 3）；同一 harness 在 8 模型下的成绩 → 检验结论是否模型无关。不是挑几对好玩配对做案例，而是覆盖整个组合空间——"harness 成为一根评测轴"的量级保障。
③ 原生保留：不拉平内部实现（最关键、最反直觉）。故意不统一提示词、工具接口、状态策略、重试逻辑（Table 1 "Native to each harness"）——因为 harness 的本质就是这些配置选择，拉平了测的就不是"真实的 harness"。与 Scaffold Effect 固定提示词的做法形成方法学对照。唯一一致化约束：默认配置出发 + 只开最小权限/工具集，不削弱也不许作弊。
④ 比较单位 = "模型–harness 配置"（Agent = Model + Harness）。三条旧路都不把 harness 当变量：静态基准抽象掉执行 / SWE-bench 类评完整系统 / AgentBench 类固定环境只比模型——HB 以配对为单位报告 = 从"背景"到"被测变量"的正式翻身。
⑤ 口径自律：配置级诊断，不是单机制因果分解。23.8 分说明"配置有影响"，但拆不出是哪个机制的功劳——那需要单零件消融（它没做，自认最大边界，也是后续切入口）。

判分：五要素全中且三处超出细则（边际分析的具体用法、"量级保障"的表述、③里的一致化约束细节），事实无一错。小 nit：①默写时把"预算/超时"两个词也带上。

**Q2：失败分类表怎么用？——判 5/5（附一条默写欠账）**

① 先记下五类 + 占比表。② 组织原则：按"对齐断裂的位置"分类——五类对应五个断裂点（输出契约/工具接口/证据基座/已提交产物/续跑状态），即执行对齐（推理/状态/动作/评测条件）在哪一环断了；Table 3 是给"执行漂移"开的诊断单。③ 非互斥：一条轨迹可同时命中多类（例：工具报错没处理 Tool → 最终 JSON 缺字段 Contract → docx 没写出来 Artifact，三类齐中）；因此总和 ≈96% 不能读成"96% 的失败被五类瓜分"，每个百分比读作"36.4% 的失败轨迹出现过该症状"，存在重复计数。④ 两个突出模式：合理≠可校验的边界（检查方向：harness 有没有把输出契约显式化、格式校验反馈有没有送回模型）；部分进展后掉链子（检查方向：工具反馈有没有进入下一步、交付物有没有被追踪、状态有没有持久化）。⑤ 实际工作流：对账单，不自带"谁的锅"——归类（打勾看命中）→ 归因（症状≠责任，是你做的：回看轨迹/对照复测/单零件消融；Contract 失败可能是模型不守格式，也可能是 harness 没暴露 schema 或没回传校验错误）→ 复测（最小改动实验验证）。一句话：表负责"哪里断的"，不管"谁的锅"；归因链是自己在表之上补的那一步。

判分：五要素全中。亮点：③用"总和≈96%"自证记得五个占比、且把重复计数的读法说对了；④把两个模式翻译成 harness 设计检查项；⑤的 Contract 双嫌疑人例子正是消融的动机。欠账一条：**占比数字没有正面默写**——现在补：Contract 36.4 / Tool 24.6 / Evidence 14.6 / Artifact 11.1 / State 9.3（大到小）。
