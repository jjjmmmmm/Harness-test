# 卡样 2 ｜ 弄坏开关 2：砍历史（KEEP_LAST_N=1）

实验：D1 Block 4 ｜日期：2026-09-22 ｜代码：`02/mini-agent-loop.py` ｜原始日志：`00-raw-console-2026-09-22.md`

- **任务**：同卡样 1。
- **现象（运行 4）**：step 0 正常读文件，step 1 正确统计出"总词数 50、唯一 16 种、apple 10 次"——然后**直接把词频当"最终答案"汇报，全程没有写文件**，目录里没有 result 文件，模型却宣布完成。
- **归因初判**：`KEEP_LAST_N=1` 每轮把历史砍到只剩最近一条、再补回系统提示词。第 1 步之后，"**把结果写入 result.txt**"这条任务指令被删掉了；模型只看得见最近的工具结果，靠猜任务是什么，猜成了"统计并汇报"。完成形态从"写文件"退化成"口头汇报"——对应 Scaffold Effect 的 **VERIFY**（声称完成但未兑现）/ Harness-Bench 的 **Artifact commitment**（推理合理但不落盘，占失败 11.1%）。
- **证据等级：仅观察**（单次运行）——但机制清楚：砍掉的是哪条消息可以直接从代码推出来，因果链短。
