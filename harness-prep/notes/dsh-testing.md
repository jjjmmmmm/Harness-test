- **三条原则引文**：
  ① （L29）"只 mock 开销高或不确定的边界（LLM 适配器、网络、时钟）；下游一切保持真实。手写替身只能证明'桥接层在搬运字节'，不能证明交付的工具行为符合断言。"
  ② （L35）"e2e 断言应重新运行命令或从外部重新读取文件；**对 agent 自身输出做关键词探测，会让作弊的 agent 通过**。断言未修改的文件逐字节一致。"
  ③ （L25）"**我们是 DeepSeek，不要吝惜真实 API 测试。**"——价值最高的是冒烟测试：启动已交付的 profile、发一条提示词、检查外部世界；能抓"单元测试全绿、产品却坏了"（有真实事故复盘 0001 背书）。
- **覆盖率口径**（L10）："行覆盖率是必要条件，但永远不是充分条件：它证明行被执行过，不证明功能按交付预期工作。"未覆盖的行往往是该删的死代码。
- **flaky 硬话**（L21）："把「只有单独运行时才通过」的 spec 读作**该 spec 的缺陷**，而不是 runner 不稳定。"
- **隔离范围**（L21）：**只隔离进程**——"端口、可预测路径、外部命名空间和继承而来的子进程都不隔离"，所以要"为每个占用的资源负责到它的 teardown"。
- **我的 D3 检查脚本三承诺**：
  1. **只读磁盘产物判分**（重跑命令 / 重读结果文件），绝不解析 agent 的"我已完成"
  2. **未动的文件逐字节比对**——顺手抓"agent 改了不该改的东西"（控制变量洁癖的自动化版本）
  3. **全量前先 2 题真题冒烟**（真 API、真产物），确认尺子在真实世界量得出对错，再放 8 题 × 8 次
