# Agent Harness 归因实验 · 三天预研

> 申请「DSH Harness 消融评测」方向前的自主预研。核心问题一句话：**Agent = 模型 × 执行层（harness），跑分把两者混在一起——固定模型、只动 harness 的一个零件，差异归因给谁、证据有多硬？**
>
> 我用 128 次受控对照实验回答了一个最小版本：把工具报错从"完整异常文本"换成 `Error: failed`（harness 的信息回传零件），看它对通过率、代价和失败形态的影响。全部数据、代码、复核记录在本仓库，**可逐条回放**。

## 30 秒结论

| 轴 | 结果 | 硬度 |
|---|---|---|
| 通过率 | 70.3% vs 79.7%，差 -9.4pp，95% CI [-24.3, +5.5] 含 0 → **按预注册写"未发现可区分的证据"**（点估计方向与假设相反，如实报告） | 预注册处置 |
| 代价 | token 中位数四格几乎相同（2.3–3.0K），但截断组为找回被删的线索扫了全盘：单次 **296K token = 完整组的 91 倍**（run-047） | 轨迹可回放 |
| 失败形态 | 完整报错组的失败是"**知情**"的（6/6 能说出原因），截断组全部"**盲目**"（不知为何失败） | 人工复核签收 |
| 模型轴 | step-3.7-flash 呈**信息量梯度**：报错信息越多、通过率越低（0/4 → 2/4 → 4/4），候选机制"认输锚定" | 仅观察（去锚探针） |

**一句话**：分数分不清的，代价和形态分得清——这与 Scaffold Effect 的核心论点在我的最小实验里同构复现。

## 实验设置（一屏版）

- **网格**：2 模型（deepseek-flash、step-3.7-flash）× 2 配置 × 8 题 × 4 次 = 128 次；另加失败指纹实验 10 次、去锚探针 8 次，合计 146+ 次真实 API 运行
- **唯一变量**：`TRUNCATE_ERRORS`（工具报错回传：完整 vs `Error: failed`）。两组**代码字节级相同**——runner 运行时拨模块开关，git diff 为零
- **固定量**：temperature=0、任务文本为代码常量、每 run 全新临时目录、判分只看磁盘产物（语义字段 + 未动文件逐字节）
- **判分先自证**：判分器元测试 8/8（发布前抓到一个会废掉逐字节比对的 Windows 换行符 bug）；复核阶段人工逐条核对全部 128 run

## 方法纪律（自认为最贴近岗位要求的部分）

1. **预注册**：处置规则（"CI 含 0 怎么说"）写在看数据之前——所以出现反常点估计时不慌也不硬拗；
2. **零 diff 对照**：不靠"改一行代码"，两组跑的是同一份代码的同一字节；
3. **验证外部世界而非自我报告**：判分只读磁盘产物，不解析 agent 的"我已完成"；
4. **尺子先量已知的东西**：判分元测试、G1 闸门构造违规样实测（测出失明，如实记录并给修复路径）；
5. **复核留痕**：改判和判例裁定全部记录理由，包括被论文原文纠正的一次（T4"合理拒绝"终裁=认输=失败）。
