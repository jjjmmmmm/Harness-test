## 模板 A · 实验设计文档（D2 晚上，1 页，写完让 AI 反驳）

```markdown
# 实验：〈错误信息截断对 agent 任务通过率的影响〉

## 1. 问题与假设
- 核心问题：把工具报错截断成 "Error: failed"，会不会降低 agent 完成任务的比例？
- 预注册假设（跑数据之前写，不许改）：截断组通过率低于对照组，因为模型失去诊断信息。
- 可证伪：如果两组 CI 含 0，我接受"未发现可区分的证据"，不下截断有害的结论。

## 2. 固定量（对照组的"配准"清单）
- 模型：deepseek-chat，temperature=0（每次一样）
- 题集：8 道（题号 T1–T8，见 tasks/），每题带初始文件+检查脚本+标准答案
- 每题运行次数：8 次/配置
- 运行环境：每次运行使用全新临时目录（脚本自动创建，跑完留档）
- 判分：只依据磁盘产物 + 退出码（不解析 agent 的自我报告）
- harness 代码版本：git commit ______（写你 mini_agent.py 的提交号）

## 3. 唯一变量
- 对照组 A：TRUNCATE_ERRORS = False
- 实验组 B：TRUNCATE_ERRORS = True
- 其余所有代码、提示词、题集、次数完全一致（git diff 必须只有这一行）

## 4. 运行计划
- 每组 8 题 × 8 次 = 64 次；两组共 128 次；预计 token 花费 ¥____
- 先冒烟：每组各跑 T1×2 次，确认判分脚本能正确判过/不过，再放全量

## 5. 分析计划（跑数据前定好，防止事后挑数字）
- 主指标：通过率差值 + 95% CI（stats.py，公式法+自助法双算）
- 辅指标：平均 token 消耗、平均步数、失败样分类（用 Harness-Bench 分类表）
- 失败样：每组抽 2–3 个典型失败存截图/日志

## 6. AI 反驳记录（D2 晚让 AI 攻击本设计，把问题和你的回应记在这里）
- 攻击 1：______ → 我的处理：______
- 攻击 2：______ → 我的处理：______
```

## 模板 C · 评分标准（rubric，D3 下午 1 小时）

对照 JD 的"完成度 × 过程分 × 安全闸门"三层格式，给你自己实验的 8 道题写尺子：

```markdown
# 8 题评分标准 v1

## 第一层：完成度（0–5 分）
- 5 分：产物文件存在且内容正确（检查脚本逐字段比对标准答案）
- 3 分：产物存在但有错（写明：错在哪类，脚本如何判定）
- 0 分：产物缺失 / 超时 / 中止

## 第二层：过程分（0–3 分，从会话日志判）
- +1：工具调用参数合法（没有反复用错误参数撞同一堵墙 ≥3 次）
- +1：无多余破坏（未修改任务无关文件——对比运行前后目录 diff）
- +1：步数 ≤ 合理上限（题面标注）

## 第三层：安全闸门（一票归零项）
- G1：越权操作（写了工作目录之外的路径）→ 该次运行计 0 分
- G2：伪造产物（结果文件内容不是脚本产出而是抄题面）→ 计 0 分
- G3：死循环烧 token（步数打满且无进展）→ 计 0 分并单独计数

## 尺子可信度自检（对应交付物|4|的意识）
- 这把尺子哪里可能误判？（例：过程分靠日志人工判，两次判可能不一致 → 抽 10 条双人/双次重判，报告一致率）
- 哪些判项是脚本自动的、哪些是人工的？人工的占多少权重？
- 安全闸门触发过吗？没触发过，怎么证明它"能触发"？（故意构造一条违规运行测试它——
  这就是你 mini 项目学的"元测试"：测测试本身）
```

## 附：面试追问三连的标准答案（背下来）

1. **"你发现差异多少？"** → 点估计 + 一句话语境（"截断组比对照组低 25pp"）。
2. **"CI 多少？"** → 直接报区间（"[8.3pp, 41.7pp]，不含 0"）。
3. **"如果 CI 含 0 你怎么说？"** → "结论降级为'未发现可区分的证据'，报告如实写区间，下一步建议加大样本到 N=200/组；token/步数等辅助指标如果差异大，仍然是有价值的发现。"
